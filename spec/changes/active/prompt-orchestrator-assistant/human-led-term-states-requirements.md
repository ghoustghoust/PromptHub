# 人工驱动：词条四态与决策溯源（需求）

## 一、背景

「词条驱动 · 人工定稿」原先只有一种状态：在选材台里点一个词，就同时进入 selected 与 locked 两个列表。这带来三个问题：

1. 用户无法表达"这个词必须原样保留"和"这个词方向对、可以改写"之间的差别，所有词都被当成逐字要求。
2. 用户无法把某个词标成"只是参考资料，模型可以不用"，于是要么不敢加，要么被强行写进结果。
3. 结果区只显示最终 Prompt，用户看不出自己选的词最后有没有生效、以什么形式生效、为什么没生效。

模型驱动一侧已经有复用、借鉴、创造、弃用四种策略；人工驱动缺少对应的"意图强度"梯度，两侧的语义不对称。

## 二、为什么这样开发

- **用户表达的是约束强度，不是布尔值。** 同一个词，用户可能要求逐字保留，也可能只想让模型参考。把两者压成 locked 会系统性放大约束、降低成稿质量。
- **排除必须是一等状态。** 只是"不加选"不等于排除：用户可能明确知道某类词会破坏画面，希望在后续自动/润色中也不要出现。
- **溯源要回答"我的词去哪了"。** 用户只判断最终结果，因此系统需要自动记录每个词条是否进入提示词、以固定要求还是模型改写的形式进入，而不是要求用户理解检索和决策内部。
- **不改变既有链路。** 四态是现有 selected / locked / excluded 三个输入数组的重新组织，加一个 reference 数组；不新增 IPC 通道、数据库表或外部服务。

## 三、行为边界

### 四态语义

| 状态 | 含义 | 进入提示词的方式 |
|---|---|---|
| 锁定 | 用户直接要求，必须逐字保留 | 系统作为固定字段写入，措辞不可改写 |
| 推荐 | 用户要求该概念出现，允许调整措辞 | 系统作为固定字段写入，模型可调整表达 |
| 参考 | 只是可用材料 | 只提供给模型参考，可复用、借鉴或弃用；不自动写入固定字段 |
| 排除 | 本轮不得使用 | 不进入任何列表；即使模型想用也会被拒绝 |

### 规则

- 新选入的词默认是**推荐**，不再默认锁定。
- **排除优先**：同一个词同时出现在选中与排除列表时，按排除处理并给出警告。
- 参考词条不消耗自动词库预算，也不作为固定事实进入最终 Prompt。
- 锁定/推荐/参考是互斥状态；一个词只有一种状态。
- 排除词不参与布局画布的"写入选中框"。
- 四态只作用于人工驱动的手动选词；不改变意图驱动下的自动检索、动态润色与角色/画师不自动推断的既有规则。
- Agent-led 模式下 excluded 仍然只影响自动选词与模型可用候选，不改变已固定的用户事实。

### 结果溯源

结果区新增"词条溯源"，逐条显示：

- 状态：锁定 / 推荐 / 参考 / 自动；
- 结果：固定写入 / 复用 / 借鉴 / 未采用；
- 进入提示词的实际片段。

说明文案必须明确：锁定与推荐由系统作为固定要求写入；参考词是否采用由模型判断。溯源是只读展示，不提供自动回写。

## 四、验收标准

1. 选材台中每个已选词条都能在四态之间切换，切换立即反映到请求输入。
2. 只标"参考"的词条不会出现在固定字段中；模型可以选择不用它。
3. 同时标记选中与排除时，结果中不出现该词条，并产生可读警告。
4. 锁定词条在结果中以固定字段形式出现且措辞与词条一致；推荐词条允许改写。
5. 结果区"词条溯源"对每个选中词条给出状态、结果与片段，且与最终 Prompt 一致。
6. 布局画布写入只包含非排除词条。
7. 中、英、繁、日、法、德、西七份文案均含新键且 JSON 合法。
8. 不新增 IPC 通道、数据库结构、外部服务或端口；保持 React → IPC → core → SQLite 链路。

## 五、非目标

- 不做词条级别的自动验证或效果评分。
- 不把参考词条强行纳入最终 Prompt。
- 不改变动态润色的检索与四策略决策逻辑。
- 不新增"推荐强度"数值或权重。
