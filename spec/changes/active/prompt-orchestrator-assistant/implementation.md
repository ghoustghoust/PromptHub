#### 5.1 已确认与当前边界

  Krea 2 不再固定为全年龄。成人是内容范围，不是所有资料无条件常驻，也不是另加模型模式。
- 镜头同时进入知识与词库：方法知识、候选词条、模型原生限制分层；接入现有
  `prompt_terms.camera`，不另造一个混合“镜头库”。
- 当前只服务 MOSS、Krea 2、MiniMax H3、Qwen-Image 2.1。Qwen 纳入范围，首批推荐首帧/改图；
  014 同时提供文生图与反推规则候选。旧模型入口是否保留只做兼容，不在新流程扩张。
- 提示词助手只产出文本和保存工作区，不生图、不生视频、不自动操作 ComfyUI，不新增端口、服务、
  provider 或依赖。外部生成后的真实图片由用户回填。
- 推荐仍按“提示词助手内增加流程创作，不做独立剧本平台”设计；生成 + 保存不是双模式。现有
  “意图驱动 / 词条驱动”与“单条创作 / 流程创作”是两个不同维度。
- 流程创作入口已确认集中在提示词助手，管理集中但运行分层；Qwen 首批仍为首帧/改图，014 自定义
  目录继续后移。旧 contract 迁移方式、历史重复色卡的正式数据映射仍未确认，不得直接全量重构或迁移。

#### 5.3 资料归属结论

- `moss-prompt`：MOSS 规则卡的复核来源；SFW/NSFW 按需读取，姿势与动作作为参考或词条来源，
  不与内置规则卡双份常驻。
- `R2VA加强版提示词模板.md`：H3 多参考规则候选，提炼进适配器，不作为附加大段写作层。
- `r18-novel-h3`：拆运行职责而不是把整包拆成可勾选正文。小说方法进知识；H3/Qwen/K2 规则进
  各自适配；连续链等待真实尾帧改进原生依赖状态；外部目录、HTML 预览和自动写文件由应用保存、
  版本与 UI 取代；逐轮角色扮演不在首批。
- `老唐电影级分镜skill-s9`：保留预览确认、连续性、空间和局部修改方法；Seedance 模板不直接
  当 H3 规则，聊天口令改为界面确认动作。
- `ai分镜实战`：只借鉴“规范事实 → 规范镜头计划 → 模型适配”的结构；不注入总控全文，不保留
  暂不服务的模型适配器，不做自动多轮质量修复。
- `斯坦尼斯拉夫斯基表演体系skill`：以 Kimi 最终稿为候选源，小说/剧本/分镜按步骤选用；旧版
  不重复导入。单动作、口型比例等是创作策略，不冒充 H3 官方限制。
- `Skill-Film-v2.00.1`：A/B/C/D/E 按产物使用，160 模块可保存与检索但每步只选少数；H 层只给
  人看，不照搬“整包必须 32K”为新策略，也不修改现有预算。
- `导演视觉风格色卡_SKILL` + `色卡-资料包`：同一导演记录的两种来源，按导演 ID 合并元数据与
  资产，不重复导入提示词正文。
- `Comfyui-Anima-Wardrobe-V6-main`：独立 Anima 插件，且许可证限制二次包装/再分发；不并入
  PromptHub 运行时或发布物，不复制其源码、词库和预设。
- `【014】加载图库节点+服装、发型、姿势、人像等6000套素材`：只接入图库数据与 Qwen 文本规则；
  Goohai 的 70+ ComfyUI 节点、前端 JS、Python、模型文件和工作流不执行、不内嵌。

#### 5.4 色卡实测与合并方案（已静态核对）

- 两边均有完整 200 个导演 ID，没有导演缺口。规范化 Unicode 路径后，共享 5,180 个文件：
  4,889 个字节级相同，264 个只有换行差异，27 个只有 JSON 序列化差异；**实质内容差异为 0**。
- `directorStyleLibrary` 独有 133 个文件：125 张 JPG、8 份 Markdown，主要是剧照及来源说明。
- 三期 SKILL 独有 60 个文件：18 张 JPG、4 份 Markdown、38 份 HTML 色卡展示页。
- 两边补集文件与对方全库交叉哈希均为 0 个不同路径字节重复。未做感知哈希/视觉相似度判重，
  因此只能声称“路径与字节内容层面无重复”，不能声称所有剧照视觉上绝不相似。
- 推荐以 `directorStyleLibrary` 为主源，三期 SKILL 只补独有资产；按导演数字 ID 形成虚拟联合
  索引，不复制成第三份约 1GB 的目录。共享正文选择一份即可，HTML 只作展示，不注入模型。
- 缩略图按明确优先级选择，不能靠文件名字典序碰运气。若只做每导演一图，无需新增资产表；
  若开放多剧照浏览，再增加资产子记录，不把多个路径拼进 `sourcePath` 字符串。
- 重导入以导演 ID/稳定身份更新并保留原记录 ID 与 `referenceItemIds`；源哈希统一换行或使用
  规范化 JSON，避免仅格式变化被误判为源内容变化。

#### 5.5 014 实测与数据映射（已静态核对）

- 整包约 6.49GB，混有图库、Qwen 规则、工作流与 ComfyUI 插件。四个可机读图库共 **5,238 条**，
  不是 6,000 条现成提示词；所有被索引引用的图片均未缺失：
  - 服装 1,407 条，8 个分类；英文关键词实际只有 1,250 个不同值，按规范化短语去重，不能按
    图片数重复造词。
  - 发型 893 条，4 个长度分类、51 个造型值；`source_id → portrait.id` 的 893 条关系全部有效。
  - 人像 1,499 条，正脸参考 893、造型参考 606。
  - 姿势 1,439 条，按“体系 + 姿势编号”是 288 组、5 种视角；全局不同姿势名 287 个。必须保留
    分组和视角，不能按记录数生成 1,439 个重复词条。
- `GHIL/自定义` 另有 729 张 WebP 缩略图与 682 张 JPG，但缺少清单元数据，不能可靠映射标题、
  词条、分组和来源。首批跳过；以后走用户人工补录/确认，不凭图片自动编身份或提示词。
- `source_assets` 建议命名空间：`ghil:costume:<id>`、`ghil:hair:<id>`、`ghil:portrait:<id>`、
  `ghil:pose:<体系>:<姿势编号>:<角度>`。`path` 存原图，`meta` 存缩略图、分类、标签、原始语言、
  分组、视角、来源关系、源哈希、内容范围与授权说明；不得触碰其他 kind 的既有数据。
- `prompt_terms` 只投影真实可执行文本：服装英文短语可去重后进入 `clothing`；镜头术语进入
  `camera`。发型/人像/姿势没有现成英文执行词的，先保留在图库，走翻译预检与用户验收，禁止
  伪造英文、伪翻译或自动提升为 validated。成人原分类与级别原值保留。
- 图库选择用于 Qwen/H3 的素材绑定，角色可分别指定身份、服装、发型、姿势、场景、首帧、尾帧；
  选图不等于自动把全部关键词或图片注入模型。需要读图时才发当前相关图片。
- 图片及原始数据许可并不完全统一，部分说明限制商用或再分发。默认本机只读挂载，图片不进入
  仓库、安装包、导出或云同步；后续若要内置，逐库核对授权，不能用插件代码的开源许可证覆盖
  图片和原始数据的权利边界。

#### 5.6 目标运行合同与数据保护

- 单条创作保持现有工作台；流程创作按需出现“原始材料 → 剧本 → 分镜 → H3 生成单元 → H3
  成稿”，允许从已有剧本或分镜直接进入，不要求从小说开始。
- 15 秒是生成单元上限/目标，不是机械切镜间隔。一个单元可含多个镜头，按节拍拆 5–15 秒；
  共享事实、角色、场景、动作结果、对白、起止状态与素材职责，最后由 H3 适配器编译。
- T2VA/I2VA/Ref2VA/Hybrid 是素材适配分支。计划可预先保存，但依赖真实首帧/尾帧的成稿必须
  等到用户回填；不得伪造已上传素材。上游修改只标记下游“需重审”，不自动批量重跑。
- Qwen 的 014 通用合同与 r18 两段式不是同一宿主格式：T2I 使用 `rewritten_prompt + wh_ratio`；
  I2I 使用 `rewritten_prompt + wh_ratio/ratio_follow`，成人适配可有 `negative_prompt`。建议以
  结构化字段为原生数据，再提供 JSON 或正向/负向复制视图，不能同时把两种显示格式都写成硬规则。
- 成人开关/范围只决定可选资源和对应规则，四个模型各自装配；不要把所有 NSFW 文本合成一个
  超级包。第一版可只统一是否启用成人，源包 L0–L5 等原始级别继续保存在元数据中。
- 知识包、模块 ID 与原始文件保留。旧 `role=contract` 不删除、不强行重导，先按包白名单分为：
  宿主专用契约（只读待适配）、模型原生规则（由适配器软引用）、方法论（改为 knowledge 并按
  步骤选）。不得用标题关键词自动批量改角色；任何数据库迁移先获明确同意、VACUUM INTO 备份，
  只操作隔离 profile，正式库不动。
- 流程正文与版本复用 Prompt/PromptVersion；`parentId` 不表示因果。流程节点另存 `kind`、
  `dependsOn`、`status`、`adapterKey`、`inputHash` 与结构 payload，正文只存引用不双写。
- 每步只发送当前规则卡、当前步骤契约、已选知识、当前节点输入与必要相邻状态；默认手动逐
  步执行，依赖/时间戳/字段校验优先确定性完成，不自动全片连跑、不自动质量循环、不静默截断
  或调低预算。

#### 5.7 推荐实施批次（每批先补测试）

1. **边界确认与止损**：新窗口先复述现状、缺口、首批范围、数据结构和风险并等确认。之后修
   资源作用域与 K2 内容范围，稳定色卡 ID；建立导入/选择回归，不先加全片流程。
2. **只读数据接入**：完成色卡联合索引与 014 四库 preview/commit、去重、缺图/缺关系报告、
   `source_assets` 查询筛选。此批不调用模型、不接入自定义目录、不执行任何包内脚本。
3. **可交互流程样板**：已有剧本 → 分镜 → 一个 H3 生成单元，支持编辑、依赖、停止、保存、
   版本和窄窗抽屉。先给用户验收交互，再接真实链路，不停留在静态 demo。
4. **真实单单元闭环**：T2VA 首条真实生成与保存，再扩首帧/多参考/Hybrid；加入 MOSS/Krea
   首帧文本、Qwen 改图文本、真实图片回填与待素材状态。
5. **知识与图库联动**：斯坦尼/Skill-Film 按步选择，014 素材角色绑定，色卡参考限量注入；
   翻译预检后再扩词库，不一次性导入全部词汇。
6. **真实引擎验收**：连续 5 次换提示词、上一轮结果回填后润色、一次本地图片反推，保存
   `live-runs.json` 与关键日志由用户判断质量。容量不足或引擎异常即停下报告，不改预算策略。

#### 5.17 工具检索降级根因修复（2026-11-26 已解决）

- **根因**：共享输出 schema 只列出 `initialPrompt / completePrompt / fields`，而工具合同末尾又要求返回
  `termDecisions`；解析器把“字段缺失”当成致命错误。模型倾向遵循 schema 省略该字段，于是只要进入
  工具循环且最终答案省略它，整条工具路径就会降级。此前实测的 3 次失败并非随机：5 个样本中恰有 3 个
  走工具路径，3 个全部失败；另外 2 个是词条驱动，不经过工具路径。
- **修复**：缺失或 `null` 的决策列表按零决策处理（0 到 32 条本就合法）；显式传入非数组或超过上限仍然
  拒绝。工具合同与动态润色合同改为明确要求“无决策时返回空数组，而不是省略字段”，并把动态润色的
  “one to 32”改为“zero to 32”，与既有校验口径一致。
- **回归证据**：缺失 / null / 非数组 / 超限四类解析用例、工具路径省略字段不降级、动态润色省略字段
  不降级均先红后绿。核心相关 5 文件 55 例、桌面定向 4 文件 19 例、i18n 48 例通过；类型检查、测试类型
  检查、根 lint、生产构建通过。
- **真实窗口实测**：隔离 profile + 词库一致性副本，5 个全新复杂提示词均一次完成，无工具降级、无
  确定性回退。需要说明：这 5 次模型都选择了零工具调用（合同允许），因此真实窗口覆盖的是“进入工具
  循环、零调用、最终答案省略决策字段”这一历史失败路径；“检索后省略字段”由集成测试覆盖。
- 实测与截图：`outputs/prompt-new-branch1d-20261126/`。未操作正式数据库或原始资料。
- 剩余边界：工具调用意愿偏低属于模型行为（合同明确零调用合法），不是本次缺陷；未增加重试轮次或
  修改引擎预算。结果页顶部标签栏在窄宽下仍会把最后一个标签截断，属于既有界面细节，未在本轮处理。

#### 5.19 工具调用与召回的真实链路（2026-11-26 已解决）

- **零调用的两个原因**：一是工具合同写着“零调用合法、无配额”，9B 模型于是从不检索；二是首轮
  `tool_choice` 只有 `auto`，没有强制。引擎探针证明 llama.cpp 在 `auto` 与 `required` 下都会返回
  `tool_calls`，所以问题在编排合同，不在引擎能力。
- **修复**：合同改为“先检查用户给出的描述槽位（光线、镜头、服装、姿势、风格、环境、道具），有则
  必须检索；只有完全没有描述槽位的请求才跳过”；尚未发生检索的轮次使用 `required`；查询必须是描述
  短语，禁止把类别名或 slotId 当查询词；输出预算按声明的上下文计算，最终轮上限 8192，避免 8K 窗口
  把答案截断；UI 无论有没有写作层都下传上下文大小，否则 32K 引擎会被按 8K 计价；截断错误附带内容
  长度与片段，便于诊断。
- **回归证据**：首轮强制、身份-only 不强制、输出预算上限、存储语法比较、决策缺失容忍均先红后绿。
  核心相关 5 文件 60 例、桌面 3 文件 9 例、i18n 48 例通过；类型检查、测试类型检查、根 lint、
  生产构建通过。
- **32K 真实实测**：隔离 profile + 90,596 条词库，5 个新提示词。5 次全部发生工具调用（每次 3–4 次
  查询、6–8 个候选），检索与召回可用；但 5 次最终 JSON 都写到 1 万字符以上并被截断，随后降级到
  动态润色，最终产出有效、无确定性回退，降级与截断原因完整记录。
- 实测与截图：`outputs/prompt-new-branch1f-20261126/`。
- 剩余边界：检索链路可用，但“工具轮直接产出完整 JSON”超出 9B 模型能力。下一步应把最终组装移到
  Core（模型只输出短决策），而不是继续提高输出上限；8K 窗口也能调用工具，但输出预算更紧，32K 才
  能同时容纳检索结果与长答案。

#### 5.21 候选采用观测与 UI 路径异常（2026-11-27 已解决）

- **Core 兜底检索**：模型有时首轮不调用工具，此前会直接接受未检索的答案。现在只要请求含描述槽位

#### 5.22 图片逆推排查（2026-11-27 已解决）

- **视觉输入格式**：图片以 OpenAI 兼容的 `image_url`（`data:image/...`）随第一条 user 消息发送；NInfer 侧 `inferVision` 开启、每图 128 merged tokens，`imageMaxTokens` 2048；单次请求超时 300 秒。
- **失败原因是大图**：1.4 MB 的原图在 UI 与 API 下都超过 10 分钟没有结果，实际是图片处理/推理耗时越过请求超时，而不是不支持视觉。换成 16 KB 的 webp 缩略图后，API 14.4 秒返回 526 字符，UI 9.1 秒返回 212 字符。
- **UI 还需要一句意图**：只上传图片、输入框为空时，模型长时间不产出；补一句 “Describe the person in the photo.” 后正常返回。reverse 的 blocker 只要求“有图或描述”，不会替用户补意图。
- **真实窗口证据**：`outputs/prompt-new-branch1h-20261127/reverse-image.json`，输出命中 woman / hair / portrait，合同为 `Reverse · No model tools`（带图时不进入工具路径，符合设计）。
- 剩余边界：大图仍需用户在导入前压缩，应用尚未自动缩图；逆推质量只按内容命中判断，未做逐项视觉事实核对。

#### 5.23 参考图自动缩放与无提示词逆推（2026-11-27 已解决）

- **“1 MB 太大”是误判**：真实 ComfyUI 输出是 2176×3872 到 7168×9472 的大图，体积 4–27 MB。应用此前
  ①在选图时直接拒绝 >10 MB 的文件；②把原分辨率整图发给视觉模型，推理超过 300 秒请求超时。所以问题
  不是“文件大”，而是**没有按视觉需要缩放**。
- **修复**：参考图在发送前统一缩放到长边 1024（JPEG 0.85），渲染层无法解码的格式才回退原图；同一逻辑
  同时用于粘贴图片和画布逆推；选图上限放宽到 64 MB，避免真实导出被直接拒绝。
- **无提示词逆推**：reverse 只上传图片、不写文本时，此前 user 消息的 intent 为空，模型会长时间不产出。
  现在由 Core 补一条标准逆推指令，并在 warnings 里说明使用了默认指令；用户自己写了意图则原样保留。
- **真实窗口证据**（ComfyUI 输出目录，全部不填提示词）：
  - 13.1 MB (2176×3872)：15.9 秒，713 字符；
  - 26.0 MB (7168×9472)：12.2 秒，346 字符；
  - 4.3 MB (1328×1776)：12.0 秒，391 字符；
  - 三张都返回了人像描述，命中 hair / face / portrait / standing 等视觉词。
- **回归**：无提示词逆推使用默认指令、用户意图不被覆盖，均先红后绿。核心 3 文件 31 例、类型检查、
  测试类型检查、根 lint、生产构建通过。
- 剩余边界：缩放后的图只保留 1024 长边，极小文字或细节无法逆推；未做逐项视觉事实核对。

#### 5.25 分支 3（一）：主 Skill 互斥与语义分层（2026-11-27 已解决）

- **主 Skill 互斥**：协议组（剧本/分镜/小说）只能由一个知识包主导。两个包同时声明同一组时，运行以

  以及服务不同步骤的不同组仍然放行。知识选择现在携带 role 与 contractGroups，选择器会在运行前给出
  同样的阻断提示。
- **共享语义与模型末端规则分层**：新增编译器，把上游事实（主体、动作、场景、构图、光线、调色、
  连续性、约束）编译一次，再追加**原样不变**的模型规则卡。同一组事实编译到 moss / k2 / h3 时，共享
