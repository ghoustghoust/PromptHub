# 润色 · 动态检索与四策略对照需求

## Product

Desktop

## 文档性质

本文件是提示词编排助手本轮新增样板的补充需求，重点说明为什么开发、解决什么问题、
用户可观察行为、边界与验收。既有编排需求仍由原文档维护；本文件不重复其完整产品说明。

## 一、完整背景

PromptHub 已把社区词段、词组、角色、画师及其他语料整理进结构化词库。当前隔离测试库
约有 9.1 万条记录，其中既含普通视觉描述，也含大规模角色与画师数据、长短不一的短语和
未经过目标模型实测的社区内容。词库规模已经足以提供专业知识，但也带来了新的使用难题：

- 原有自动润色是在模型生成前，由程序按固定类别和字符串相关度预先插词。模型只能处理
  已经递给它的内容，不能决定查什么、查多少、何时换查询、何时停止以及何时不用词库。
- 固定数量与统一上下文额度会让排在前面的类别先占满空间，后面的光影、构图、镜头等
  语义槽位可能得不到候选。候选数量不等于有效信息数量。
- 长句包含更多关键词，容易在简单累加评分中获得优势，但“内容更长、命中更多”不代表
  “语义更准确”。大量近义或近重复候选也会挤占模型注意力。
- 角色名是身份锚点，外观、特殊器官和相似造型只是关联属性。仅凭外观语义相似不能确认
  角色身份，也不能自动加载整份外观描述。画师还涉及提示词文本与独立风格参数两种不同
  生效方式，不能统一当作普通描述词。
- 社区收录不代表语义正确，更不代表在特定底模、LoRA、任务和工作流中有效。普通用户不会
  审核全部语料，也不应被迫理解召回分数、候选列表或创造权限才能使用润色功能。
- 用户最终只需要判断润色结果是否更符合意图。系统必须自行保留决策依据，不能把过程验证
  责任转嫁给用户，也不能仅凭一次采用或一次点赞就宣称词条已经通过生图验证。

本地模型已经具备结构化输出能力，但单次调用并不等于完整的知识使用流程。本轮因此选择
“润色 + 动态检索 + 四策略对照”作为可交互样板：原始提示词提供了明确的语义基准，最容易
观察模型是否保留原意、是否合理使用词库，以及是否发生错误具体化或无关扩写。

## 二、开发目标

在不把整库塞入上下文、不牺牲模型创造力的前提下，让润色流程形成按需知识使用闭环：

1. 模型先理解原始提示词，识别真正需要知识支持的语义槽位。
2. 程序根据模型提出的查询，从词库提供经过筛选、去重和预算控制的少量候选。
3. 模型对每个槽位独立决定复用、借鉴、创造或弃用，而不是被迫使用自动预插词。
4. 用户直接看到原始语义、处理结果、关联词条和简要理由，并能按四种策略筛选对照。
5. 无匹配、零查询和完全不使用词库都必须是正常结果，不得为了体现词库价值而强行贴词。

本轮要证明的是“词库能否以可解释的方式参与润色决策”，不是预先证明最终生图质量一定
提高。后者仍需在相同底模、LoRA、工作流和参数下进行结果对照。

## 三、范围与硬边界

### 本轮包含

- 仅用于意图驱动、自动编排方式下的提示词润色。
- 自然语言 Caption 与动漫 Tags 输出。
- 模型按需发起查询，程序执行结构化词法检索，最多允许一轮补充查询。
- 复用、借鉴、创造、弃用四种策略的逐项对照与筛选。
- 按全部、共用、二次元、真人、3D 选择检索范围；具体题材同时包含共用词条。
- 保留既有原始提示词与完整润色结果的左右对照、存入库和收藏等主流程。

### 本轮明确不做

- 不接 Embedding、向量数据库、重排序模型或全库向量化。
- 不调整 32K 上下文，不接 256K，不改变 KVMem 配置。
- 不自动识别或推断角色、画师，不根据相似外观加载角色属性。
- 不自动注入画师名、风格参数、LoRA 触发词或特殊器官描述。
- 不改动人工定稿与精确 Layout 的既有行为。
- 不自动操作 ComfyUI，不把润色结果直接视为生图验证结果。
- 不修改正式数据库，不新增词库记录，不让生成结果自动写回社区词库。
- 不引入外挂页面、独立应用、额外服务或第二套模型配置。

所有词库读取只能发生在隔离测试环境。社区词条即使被检索到，也仍按原有来源和验证状态
对待，不因进入候选或最终被采用而自动升级为已验证知识。

## 四、与 RAG 的关系

本轮属于结构化检索增强，但不是“全库向量化后按相似度取前若干条”的实现。

精确匹配、文本规范化、关键词检索和按类别查询同样属于知识检索。当前样板先验证这些
低成本方式能否支撑模型决策。Embedding 只作为未来改善跨语言改写和自然语言近义召回的
候选手段，不能替代角色实体解析、触发词精确匹配、冲突约束和最终语义判断。

语义相似也不等于可以平替。相反光照、上下位概念、同名或近似外观角色、明确镜头参数，
都不能只凭相似度自动替换。

## 五、润色工作流程

1. **理解原意**：保留原始主体、动作、关系、否定、风格与明确参数，不把润色变成重新创作。
2. **规划查询**：模型只选择需要知识支持的槽位，可给出一个主要查询和一个改写查询。
   首轮最多四个槽位；原提示词已经足够清楚时允许零查询。
3. **执行检索**：程序按槽位独立召回候选，不因前一个槽位已经占满额度而停止处理后序槽位。
4. **决定是否需要补充查询**：候选确实不足、过宽或方向错误时，模型可提出最多两个修订或
   新增查询。补充后必须定稿，整个流程最多两轮检索，不允许无限自治循环。
5. **形成四策略决策**：模型只引用实际收到的候选，结合原意选择处理策略并组织完整结果。
6. **校验与展示**：系统检查决策与候选的对应关系，展示策略对照和检索摘要。模型或结构
   校验失败时必须明确降级，不能把未经决策的自动候选直接拼成正式润色结果。

## 六、候选检索与注意力控制

- 文本匹配需处理大小写、空格、下划线、常见转义和中英文字符差异，但不能把正则或模糊
  匹配误认为语义等价判断。
- 相关性评分不得按词条长度直接加分，也不得简单因长句包含更多词而持续累加优势。
- 关键词评分应带长度归一化，并结合精确命中、短语命中与查询覆盖情况排序。
- 完全重复和高度近重复的候选不得成组占满展示名额；探索性查询应比普通精确查询保留更多
  差异，但不能为了多样性引入相反或无关内容。
- 每个激活槽位拥有独立且公平的候选预算。未激活槽位不占预算，无匹配合法留空。
- 长短语的上下文成本与相关性分开计算；长候选不能仅凭长度垄断槽位预算。
- 最终成稿只使用已接受候选和原始表达，不继续携带全部淘汰候选。
- 当前只使用词法与结构信息，不假装拥有语义向量、实体关系或目标模型实测能力。

## 七、四种知识使用策略

| 策略 | 含义 | 必须满足的条件 |
| --- | --- | --- |
| 复用 | 直接采用词条或其既有模板 | 语义准确、使用方式匹配，不引入原意之外的具体事实 |
| 借鉴 | 以词条为语义或表达锚点，再补齐空间、关系、程度与上下文 | 必须能追溯到实际候选，扩展不得改变锁定事实 |
| 创造 | 没有合适候选时，由模型保留原意并重新组织表达 | 不伪造词库来源，不把创造内容冒充社区已验证词条 |
| 弃用 | 不采用当前候选，或整个槽位不需要词库 | 是正常决策；可保留被拒绝候选用于解释，不强行生成替换内容 |

四种策略可以出现在同一次润色中。完全不用词库不代表功能失败，强行提高词库使用率反而
属于偏差。创造只改变表达和合理细节，不得篡改主体、否定、明确构图或用户指定风格。

## 八、角色、画师与社区数据保护

- 角色身份必须依靠明确名称或可靠实体解析，不能仅凭外观相似度确认。本轮自动检索直接
  避开角色类别，用户显式选择的角色词条仍按既有锁定语义处理。
- 画师类别不参与本轮自动润色检索，避免大规模画师数据挤占普通视觉描述，也避免把画师名
  错误写入不支持该语法的提示词正文。
- 成人词条不作为普通润色的自动扩展素材；用户显式选择不由本轮新逻辑改写或删除。
- 词条的模型适用信息为空时，只能说明没有额外限制或适配未知，不能展示为“全模型已验证”。
- 检索正确、社区收录和生图有效是三种不同事实，界面不得混用“已验证”表述。

## 九、交互要求

- 用户选择润色后，应能理解当前使用的是按需检索，而不是旧的固定预插词。
- 检索范围选择只在当前样板适用时出现，不增加无关任务的控制项。
- 成功结果默认进入“策略对照”，同时保留原有完整结果对照入口。
- 四种策略与全部筛选显示真实数量；筛选只改变查看内容，不修改生成结果。
- 每项决策左侧展示原始语义，右侧展示处理结果；弃用时明确说明不采用候选。
- 复用与借鉴展示关联词条，保留中英信息；创造不伪造关联词条，弃用可展示未采用候选。
- 检索摘要展示实际轮数、查询数和送入决策的候选数，不展示虚构的召回规模或质量评分。
- 普通窗口中文字必须自然换行，不能因新增对照而挤压、截断正文或让主操作失去可用性。
- 降级结果继续明确标识，策略对照不伪装成完整模型决策。

## 十、验收标准

### 主流程

1. 在隔离测试环境输入一段真实原始提示词并执行润色，能够看到按需查询后的完整结果，
   而不是每个类别固定插入相同数量的词条。
2. 换用不同原始提示词，查询槽位和查询内容会随语义变化；无需知识时允许零查询。
3. 结果页可按四种策略筛选，数量与逐项内容一致，原始语义和处理结果可对照。
4. 复用与借鉴只能关联实际提供给模型的候选；创造没有伪造来源；弃用没有强行替换文本。
5. 无匹配时仍能得到保留原意的结果，不会为填满类别而引入无关词条。

### 检索与约束

6. 长句不因长度本身获得额外相关度优势；近重复候选不会简单占满一个槽位的展示名额。
7. 后处理槽位不会因前面类别先耗尽统一预算而直接失去查询机会。
8. 选择具体题材时同时包含共用词条；角色和画师不因外观或风格相似被自动推断。
9. 补充查询至多发生一轮，之后必须定稿；不会发生无限检索。
10. 模型失败、结构失败或非法候选引用时有明确降级或修正，不把未决策候选拼入正式结果。

### 兼容与用户体验

11. 人工定稿、精确 Layout、完整结果左右对照、存库和收藏行为保持既有契约。
12. 普通窗口下策略卡、双语文本和筛选操作可用，不出现正文截断或主按钮不可用。
13. 所有可见新增文本具有完整本地化，不依赖单一语言硬编码。

### 效果边界

14. 上述验收只能证明动态检索与决策流程可用。是否提高目标模型的实际生图效果，仍需
    在固定生成条件下比较原始提示词、旧静态选词和动态润色三组结果，不能提前宣称。

## 十一、后续裁定依据

只有在真实查询集证明当前词法检索存在稳定漏召回后，才评估多语言 Embedding；只有候选
已经召回但排序仍频繁错误时，才评估重排序模型。角色与画师应先补实体和使用方式约束，
不能期待更大的向量模型自动解决身份与参数路由。

上下文扩展同样不是本轮前置条件。若未来真实润色状态超出正常预算，应先检查是否重复
携带淘汰候选、完整历史和无关系列数据，再决定是否需要更长上下文。
