# 词库检索评测基线（隔离测试库 · 91k）

## 结论先行

当前词法检索在「表达级精确命中」上可靠（模型可见面 28/28 表达登顶），禁查类别、domain 路由、长度去偏置、近重复抑制、零预算降级全部经真实语料验证。主要缺口是**单词/短片段查询的 top6 可见度**（英文单词片段 B 面 12/21、A 面 9/21）。按需求文档 §十一 的裁定条件：本轮数据尚不能证明多语言 Embedding 必要，也不能证明重排序模型必要；应先做检索深度/预算的程序化 A/B，再评估 Embedding 与重排序。三项程序化改进（短查询深度升级、折叠审计、重复行合并）已落地并在同一套件上复测，见第六节。

## 一、方法

- 数据源：`start-prompthub-test.bat` 隔离手工测试 profile 的 `profile/data/prompthub.db`（约 9.1 万行）。只读打开，评测不写库。
- 地面真值：15 个允许检索类别（style/base/body/face/hair/clothing/accessory/pose/expression/environment/weather/props/lighting/composition/camera）每类按 `en` 排序确定性 stride 采样 2 条，共 28 条；deprecated 除外。artist/character/nsfw 不参与采样。
- 双检索面：
  - A 面 = `PromptVocabDB.searchTerms`（SQLite LIKE，按 en 排序，limit 60）——选材台、IPC 搜索与浏览器面对用户可见的行为。
  - B 面 = 动态润色检索组（`runDynamicPolish` + 脚本化 LLM 规划查询）——模型在编排消息中实际收到的候选（经排序、去重、槽位预算）。
- 套件：`packages/core/tests/retrieval-evaluation.test.ts`；未设置 `PROMPTHUB_EVAL_DB` 时整体跳过，不进入常规回归。
- 重跑（仓库根目录）：
  ```
  $env:PROMPTHUB_EVAL_DB="<隔离库 prompthub.db 路径>"
  $env:PROMPTHUB_EVAL_OUT="<报告 JSON 输出路径>"
  pnpm --dir packages/core exec vitest run tests/retrieval-evaluation.test.ts
  ```

## 四、发现

1. **精确表达可靠**：B 面 28/28 表达登顶，A 面 @60 全命中。精确/短语奖励与长度归一化评分在真实社区语料上成立，未观察到长句靠长度占优。
2. **跨来源重复表达**：7/28 样本在 LIKE 池内有规范化同义文本行；3/28 样本的具体 id 因近重复抑制不可见（`sketch` 两行、`lower body` 两行、`from behind`/`from_behind`）。表达式级召回完整，id 级召回 25/28。对复用策略的 termId 溯源有实际影响：模型只能引用去重后幸存行。建议数据回填阶段合并同表达行或标记首选行。
3. **单词片段召回是主要缺口**：单 token 查询 B 面 12/21（57%）、A 面 9/21（43%）。焦点深度（focused，候选上限 6）下，正确表达常被更短/更高频的邻近表达挤出 top6。这直接定义了下一个检索改进点。
4. **中文片段**：B 面 25/28、A 面 26/28。未命中多为 2–3 字短标签被 bigram 匹配到的大量候选挤出，与英文单词片段同源。
5. **反义不可区分（记录在案）**：本轮 `soft` 相关查询的 top6 未出现 `hard` 行（精确/短语奖励主导），但词汇层面无法区分反义是结构性的——不能靠更大 Embedding 解决，需冲突关系与规则卡片参与。
6. **禁查与路由**：artist/character/nsfw 零候选由检索器强制（即使模型规划了这类查询）；domain 路由在真实数据上成立；model/series 路由因语料无受限行而不可测，已由单元层证明。
7. **预算**：默认 900 与小额预算下槽位公平成立；零预算正确降级为「无候选 + 明确警告」，不会静默拼词。

## 五、对需求文档 §十一 裁定的输入

- **Embedding（暂不投入）**：中文片段 25/28 已由 LIKE + CJK bigram 覆盖，跨语言改写并非当前主要矛盾；单词片段缺口是「top6 可见度」问题，不是「漏召回」问题（LIKE 池内正确表达存在）。若程序化深度调整后缺口仍在，再评估多语言 Embedding。
- **重排序（暂不投入）**：精确面已登顶，重排序无增益空间；其潜在价值仅在单词片段面的语义排序，排在程序化深度/预算调整之后。
- **先行程序化手段（建议下一批）**：① 单词/短片段查询自动升 exploratory 深度或提高 focused 上限；② 近重复抑制时保留 id 级可追溯的首选行标记；③ 数据回填合并跨来源同表达行；④ 短 zh 标签的 bigram 挤出缓解（查询侧短语化或候选侧去高频词）。

## 六、程序化改进与复测（2026-11-20，同一套件）

按第五节裁定的先行手段落地三项，并在同一隔离库上复测。

| 改进 | 落地方式 | 边界 |
| --- | --- | --- |
| 短查询深度升级 | 单 token（含两个 CJK 字符）查询在检索器内部确定性升为 `exploratory`，结果组带 `escalated=true`；模型无需自己判断深度 | 只放宽候选上限，不改变排序规则；仍受槽位预算约束 |
| 折叠审计 | 近重复吸收的候选以 `collapsedTerms` 随组返回；模型被告知只引用幸存候选 id | 仅审计可见性，不改变幸存行选择（仍取排序最高者） |
| 重复行合并 | `PromptVocabDB.mergeDuplicatePromptTerms()`：同类别 + 同规范化 `en` 分组，优先保留已验证/有 `zh` 的行，关系与验证记录先重映射再删除被吸收行；可重复执行 | 只处理完全同表达行，不做语义合并；合并前用 `VACUUM INTO` 备份 |

隔离库合并结果：**91,168 → 90,596 条（吸收 572 行）**，合并后重复表达组 0、自环关系 0、孤儿关系 0、孤儿验证记录 0；幂等重跑合并 0 行。

复测数字（同一套件、同一隔离库）：

| 查询类 | 查询数 | A 面 @6（基线 → 复测） | B 面 id 登顶（基线 → 复测） | B 面 @6（基线 → 复测） |
| --- | ---: | --- | --- | --- |
| 精确英文表达 | 28 | 26 → **28** | 25 → **28** | 25 → **28** |
| 中文片段（zh 前 4 字） | 28 | 26 → **27** | — | 25 → **26** |
| 英文单词片段 | 22 | 9 → **12** | — | 12 → **17**（57% → 77%） |

复测样本因合并后行数变化，确定性 stride 采样范围随之变化（英文单词片段 21 → 22 条，精确面与中文片段仍各 28 条）；跨表比较以比率为准，与上节绝对值不逐一对应。

结论：重复行合并消除了精确面 id 级的溯源歧义（表达级与 id 级现在一致）；短查询深度升级把单词片段的模型可见命中从 57% 提到 77%，且未引入长度偏置或重复泄漏（不变量类仍全部通过）。改动后 core 编排套件 35/35、词库 DB 套件 25/25。

## 七、第二轮收敛（排序与冲突过滤，2026-11-21）

| 尝试 | 实测 | 处置 |
| --- | --- | --- |
| 精确命中置顶（`en` 或 `zh` 完全相等优先，其余保持 `en` 升序） | 样本数字无变化（合并后精确面已是 28/28），但保证精确标签不受字母序与 limit 影响必然可见 | 保留，附单元测试 |
| 前缀 / 整词 / 子串三级排序 | 中文片段 A 面 27 → 28，但英文单词片段 A 面 12 → 8（大量前缀候选挤掉中位匹配） | **回退**，仅保留精确置顶 |
| 冲突感知候选过滤 | 与用户已选/锁定词冲突的候选在展示前剔除，组内 `excludedConflicts` 留痕；模型若仍引用已剔除 id，该决策降级为 `create` + 警告，不再整轮降级 | 保留，附单元测试 |

复测（同一隔离库）：精确表达 28/28、中文片段 A 27 / B 26、英文单词片段 A 12 / B 17，与第一轮一致，无回归。

结论：单词/短片段剩余的可见度缺口，本质是「多个都有效的行竞争同一 top6」——评测真值取自任意采样行，词法层没有信号能判定哪一行才是用户想要的。继续调权重属于对合成指标的过拟合；该缺口作为「Embedding / 重排序是否有增益空间」的边界证据保留，不再以调参方式处理。

## 八、任务感知重排复测（2026-11-22，同一套件）

给候选增加与分数无关的关系标签（等价 / 更窄 / 更宽 / 相关 / 相反），并按任务策略过滤与
加权：逆推只留等价，扩写偏好更窄，润色等价优先，相反在四种文本任务中一律排除。复测使用
同一隔离库、同一评测套件与同一采样。

| 查询类 | 查询数 | A 面 @6（上轮 → 本轮） | B 面 @6（上轮 → 本轮） | 顶部候选关系分布 |
| --- | ---: | --- | --- | --- |
| 精确英文表达 | 28 | 28 → **28** | 28 → **28** | 等价 26、相关 2 |
| 中文片段 | 28 | 27 → **27** | 26 → **26** | 等价 20、更窄 7、相关 1 |
| 英文单词片段 | 22 | 12 → **12** | 17 → **17** | 等价 10、更窄 12 |

结论：

- 关系重排没有改变本样本的 top6 命中，说明它是“解释与方向”的改进，不是召回数字的改进。
- 英文单词片段的顶部候选有 12/22 是“更窄”的长标签，而不是精确单词行：这与第七节的判断
  一致——缺口是多个有效行竞争同一个 top6，而不是词法层找不到正确行。
- 因此继续不接 Embedding、不做全库向量化。若还要提升，先做检索深度/槽位预算的程序化
  A/B；只有真实查询集证明“正确行根本不在 LIKE 池内”时，才评估多语言 Embedding。
- 逆推“只接受等价”可能让长句查询返回空候选；这是有意为之的保守边界，空结果由模型改写
  或用户补词处理，不用近似项凑数。

## 九、边界

- 本基线证明检索面行为，不证明生图效果；动态润色的模型决策质量仍需真实模型与 A/B/C 出图对照验收。
- 评测使用隔离手工测试 profile 数据库，未触碰正式 profile；只读打开，无写入。
- 采样为确定性 stride（每类按 en 排序取 2 条），重复运行数字一致；样本量 28，类别内长尾分布不代表全部 18,819 行。
