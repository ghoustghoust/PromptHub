# prompt/new 整合：短期纠偏与开发顺序

## Product

Desktop

## 文档地位

本文记录当前已确认的整合目标、因果关系和短期开发顺序，不列接口协议与代码，也不另设一套验收口径。
权威需求继续由 `design.md` 持有，实施动作、验证结果和遗留项仍回写 `implementation.md` 第 5 节。

## 1. 原始目标与当前判断

目标不是把 `prompt/new` 全量搬进应用，而是让其中有价值的提示词、规则、方法、参考和素材，在 PromptHub 内以可理解、可控制的方式服务提示词创作。

当前确认以下方向：

- 管理上集中在提示词助手，不另建与提示词助手并列的剧本平台或素材平台。
- 集中管理不等于所有资源、所有按钮、所有步骤同时出现在一个页面。运行时必须按任务、角色、步骤和依赖展示当前有用的内容。
- 提示词助手只产出文本并保存工作区，不生图、不生视频、不自动操作 ComfyUI。
- 当前只服务 MOSS、Krea 2、MiniMax H3、Qwen-Image 2.1。其他模型资料不能反向扩张产品范围。
- 已开发内容可以保留、改造或撤回，但不能因为已经写成就继续堆叠，也不能因界面失误删除底层能力和用户数据。

## 2. 为什么当前效果会显得混乱

当前问题不是资料太多本身，而是几条不同的因果链被压成了相似的卡片和勾选动作：

1. “导入资源”与“本轮使用资源”被放在一起，用户难以判断导入后发生了什么。
2. 色卡会进入本轮参考，014 素材却只保存勾选数量；相同外观对应不同结果。
3. 素材尚未绑定角色和生成单元，却提前提供全局选择，选择缺少后续动作。
4. 单条创作需要的配置与流程创作的依赖关系混在同一层，无法判断谁先谁后、谁决定谁。
5. 旧知识模块的参考角色与专用导演色卡并存，历史数据尚未完成只读盘点和明确的收口方案。
6. 导入入口要求用户理解来源目录结构，没有先解释资源类型、读取范围和导入后的用途。

因此，短期先恢复“每个动作都有明确对象和结果”，再开发新流程，不继续补一个更大的资源浏览器。

## 3. 统一入口，但不混成一种模式

### 3.1 管理集中，运行分层

提示词助手负责统一管理：

- 提示词与系统提示词；
- 模型输出规则；
- Skill 与当前步骤契约；
- 可复用知识；
- 导演色卡等视觉参考；
- 词条；
- 图片素材索引；
- 单条创作与流程创作的文本产物。

运行时只装配当前步骤所需内容。管理上的“都在里面”不能理解为每轮都注入、都常驻或都显示。

### 3.2 不是“生成 + 保存”双模式

生成和保存是同一创作闭环的两个动作，不构成双模式。

真正需要区分的是两个正交维度：

- 引导方式：意图驱动，或词条驱动。
- 创作结构：单条创作，或按依赖推进的流程创作。

普通扩写、润色、反推、编辑仍然是单条创作。只有任务确实需要中间产物和依赖时，才展开为流程创作。

### 3.3 剧本不是独立平台

大纲、剧本、分镜和生成单元是可编辑、可保存、可版本化、可作为后续输入的中间文本。它们属于提示词创作链，不扩张成独立剧本管理平台。

## 4. 各类资料如何进入系统

### 4.1 提示词与系统提示词

用户可复用的提示词和系统提示词进入现有提示词管理体系，保留用途、正文、版本和来源。

模型原生输出规则不能再作为一份普通系统提示词与适配器双份常驻。它需要成为规则卡或适配依据，否则同一规则会在多个位置重复生效并增加负载。

### 4.2 Skill 按职责拆分，而不是按文件类型一刀切

每个 Skill 先判断它解决什么问题：

- 规定 Caption、Tags、Layout 等输出语法：进入对应模型规则。
- 规定某个步骤怎样执行、确认和输出：保留为该步骤的执行契约。
- 提供可复用的方法论：进入知识库，按任务和步骤选择。
- 提供色卡或视觉参考：进入参考库，限量使用。
- 规定多步产物的先后、输入和确认点：转化为流程方案，而不是整包常驻。
- 包含自动脚本、ComfyUI 节点或外部工作流：不执行、不内嵌，由应用自身的保存、版本和界面能力替代。

大纲级 Skill 可以指导流程，但不能因为其内容全面，就在每一轮把全文注入模型。

### 4.3 镜头同时进入知识与词库，但不混层

景别、运镜动机、轴线、构图、连续性、首尾帧组织方法属于可选知识。

可执行的镜头术语和中英表达进入现有镜头词条。模型能否接受某种结构、时长或输入方式，仍由对应模型规则决定。

姿势素材的观察角度只是素材属性，不能自动当成运镜指令。

### 4.4 成人分支保留

成人内容是任务的内容范围，不是新模型模式。MOSS、Krea 2、MiniMax H3、Qwen-Image 2.1 均保留成人适配路径。

已有的 NSFW 知识、词条、提示词和原始级别不能因整合被删减。开启范围只表示允许选择相符资源，不代表每轮强制成人内容，也不代表把全部成人资料整包注入。

## 5. 色卡：接续被中断的合并任务

旧、新色卡不是两个应当互相替代的产品。现有静态盘点已经表明：两边都有完整的 200 个导演身份，正文实质内容没有差异，但 JSON 表达、图片和展示资产存在互补关系。

因此结论是：

- 不是“文件完全重叠”，而是“导演身份与正文高度重叠，资产可以互补”。
- 按导演数字身份形成一个逻辑记录，不重复导入正文，不建立第三份重复目录。
- 一个来源提供主正文与主元数据，另一个来源补充独有图片和展示资产。
- 同源重导入保留记录身份和用户已有选择。
- 每轮最多选择三张色卡。三张是并列视觉参考，没有先后顺序，也不构成因果关系。
- 色卡只影响色调、光线和构图方向，不替代模型规则，不堆导演姓名，不把整库图片送入模型。

当前底层联合索引和单缩略图能力可以保留。多剧照与完整展示资产并集尚未完成，不能宣称合并任务已经全部结束。

历史数据库中如果已经存在重复导演记录，只做只读盘点和显式映射方案；未经单独确认，不删除、不迁移、不用重新导入清库。

## 6. 014 图库：先保留索引，选择必须回到使用场景

首批只接服装、发型、人像、姿势四个有明确索引的库，共 5,238 条：

- 服装 1,407 条；
- 发型 893 条；
- 人像 1,499 条；
- 姿势 1,439 条。

图片保留在本机只读来源，索引保存分类、标签、分组、视角和来源关系。`自定义` 目录缺少可靠清单，继续跳过。

素材的真实用途是角色与生成单元绑定，例如身份、服装、发型、姿势、首帧和尾帧。选图不等于把全部关键词或全部图片注入模型，只有当前步骤确有需要时才读取相关内容。

因此撤回“全局图库勾选并保存数量”的交互。以后应在角色和生成单元已经存在时提供绑定入口；推荐首版每个角色的每个素材槽位单选，姿势按姿势组与视角处理。该细节随角色绑定设计一并验收，本轮回撤不实施。

服装英文短语等真实文本只有在翻译预检和用户验收后才投影为词条，不能按图片数量重复造词。

## 7. 流程创作的因果链

### 7.1 共享创作链

推荐因果链为：

原始意图或已有文本
→ 必要的大纲/剧本
→ 可审阅的分镜
→ 面向生成单元的素材与事实准备
→ 当前模型适配
→ 文本成稿
→ 保存与版本
→ 用户验收或回填真实图片

每一步只消费当前步骤所需的规则、知识、输入和必要相邻状态。上游修改只标记下游需要重审，不自动批量重跑。

用户可以从已有剧本或分镜进入，不强制从小说或大纲开始。

### 7.2 H3 生成单元

H3 以不超过 15 秒的生成单元组织输出。15 秒是单元上限，不是机械切镜间隔；一个单元可以包含多个镜头，按动作和节拍决定边界。

剧本和分镜先保持模型无关的共享事实：角色、场景、动作结果、对白、起止状态和素材职责。最后由 H3 适配为当前生成单元的文本。

其他模型可以使用同一上游剧本和分镜方法，但不能把 H3 的原生输出格式冒充通用格式。多参考、首尾帧和混合输入同理：共享准备逻辑，分别适配目标模型。

### 7.3 首尾帧与多参考的依赖

计划阶段可以声明需要首帧、尾帧或参考图，但依赖真实图片的成稿必须等待用户回填。

因果顺序是：

声明素材职责
→ 用户准备或回填真实图片
→ 校验当前依赖已满足
→ 生成对应模型文本

不能伪造已上传素材，也不能把图片选择数量当成依赖已经完成。

## 8. 本地模型负载为什么增加，以及怎样控制

导入文件和建立索引本身不会直接增加每轮模型负载。真正增加负担的是：

- 常驻的整包契约和大段知识正文；
- 与当前步骤无关的模块重复注入；
- 多轮工具调用和过长的输出；
- 不必要的整库图片或视觉输入；
- 同一规则同时存在于规则卡、系统提示词和知识模块。

因此控制顺序必须是：

先识别当前步骤
→ 只选择当前步骤所需资源
→ 用同一来源计算预算与实际输入
→ 记录本轮实际注入和 token
→ 再判断是否需要优化

继续执行现有预算阻断，不静默截断、不丢模块、不修改引擎预算。当前没有充分的负载对比测量，不能宣称已经完成性能优化。

## 9. 统一操作逻辑

### 9.1 资源导入

导入是资源管理动作，不是本轮生成动作。

用户应先选择资源类型，再选择来源。应用识别目录结构，说明将读取什么、跳过什么、导入后能用在哪里，预览确认后才写入索引。

色卡的多个互补来源可以联合预览；014 图库一次处理一个明确的图库根目录，不提供无效的多目录选择。

### 9.2 色卡选择

色卡属于本轮视觉参考：

- 多选，最多三张；
- 并列生效，无顺序含义；
- 查看详情与改变选择是两个明确动作；
- 已选清单、剩余名额和实际作用始终可见。

### 9.3 素材绑定

素材不提供脱离角色的全局勾选。

只有在角色和生成单元上下文中，才出现“为哪个角色、哪个槽位、哪个生成单元选择素材”的动作。界面必须能回答素材用在哪里、何时生效、还缺什么依赖。

### 9.4 旧参考数据

旧知识模块的参考角色不再继续扩张。先确认现有数据与真实使用情况，再决定保留、映射或撤回；任何正式数据迁移都需要单独授权和备份。

## 10. 短期开发顺序

### 当前：止损与规范恢复

撤回最近两项导入界面/IPC改动，保留底层服务、联合索引、四库导入能力和全部数据。

补回归证据，确保：

- 工作台不再出现无后续作用的素材勾选；
- 色卡既有多选、上限、持久化和参考注入不被破坏；
- 底层色卡联合索引与 014 四库服务测试仍然通过；
- 不操作正式数据库。

### 下一步：可交互流程样板

已有剧本 → 分镜 → 一个 H3 生成单元，先验收编辑、依赖、停止、保存、版本和窄窗操作，再接真实模型。

### 随后：真实单单元文本闭环

先完成一个 H3 文生视频单元的真实文本生成与保存，再按依赖扩首帧、多参考、混合输入，以及 Qwen 首帧/改图文本。

### 最后：知识与图库联动

在角色和生成单元已经存在后，再恢复素材绑定界面，按步骤选择知识与色卡，并进行真实负载测量。

## 11. 当前明确不做

- 不继续开发全局素材库勾选。
- 不接入 014 `自定义` 目录。
- 不执行资料包脚本，不接 ComfyUI 节点或工作流。
- 不新增模型、供应商、端口或第二套配置。
- 不做全片自动连跑和自动质量循环。
- 不把全部知识、词条、色卡或图片整库注入。
- 不做正式数据库迁移、历史重复清理或原始文件删除。
- 不在缺少真实运行证据时宣称提示词质量、生成效果或性能已经改善。

## 12. 短期验收标准

- 用户能分清“导入资源”“本轮参考”“角色素材绑定”三种动作。
- 界面不存在只有勾选计数、没有实际用途的选择。
- 色卡同源合并不重复正文，已有记录身份与选择保持稳定。
- 流程中每个产物都有明确输入、依赖、确认点和下一步用途。
- 每一步只注入当前需要的内容，预算与实际输入使用同一来源。
- 旧数据、原始资料和底层服务不因界面回退而丢失。
- 宽屏、窄窗和关键操作使用隔离真实窗口验收，质量判断最终由用户作出。
