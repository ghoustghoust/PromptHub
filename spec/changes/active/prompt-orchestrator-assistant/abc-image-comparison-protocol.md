# A/B/C 出图对照协议（工装）

> 目的：在**同一底模、同一参数、同一种子**下，比较三种提示词来源的实际出图差异，而不是比较文字本身。
>
> 状态：工装就绪；执行依赖可用的生图后端（PromptHub 生图网关或 ComfyUI）。当前 ComfyUI 未启动，因此只完成清单与盲评表。

## 一、三组定义

| 组 | 来源 | 说明 |
| --- | --- | --- |
| A | 原始自然语言 | 用户原话，不做词库选词 |
| B | 静态选词 | 旧流程：程序按类别固定预插词条 |
| C | 动态检索 + 四策略 | 当前润色链路：模型规划查询、Core 检索、复用/借鉴/创造/弃用 |

三组必须来自**同一个意图**，只改提示词来源；不得为 C 额外补充用户没说过的事实。

## 二、执行步骤

1. 选 6–8 个案例，覆盖：人像、静物、场景、动漫、光影、镜头、反推、润色各至少 1 个。
2. 对每个案例，用对应流程产出 A/B/C 三版 Prompt，填进 `cases.json`（格式见 `cases.example.json`）。
3. 运行：

   ```
   node scripts/build-abc-blind-sheet.mjs --cases cases.json --out outputs/abc-image-comparison-<date>
   ```

   产物：`manifest.json`（每条出图请求 + 盲码）、`score-sheet.csv`（盲评表）、`answer-key.json`（盲码对照，评分结束前不要打开）。
4. 按 `manifest.json` 逐条出图：
   - 同一 `model`、`size`、`steps`、`seed`（同一案例三版必须同种子）
   - 固定采样器/调度器/CFG，关闭任何提示词增强
   - 文件名用 `<caseId>-<blindCode>.png`，不要带 A/B/C
5. 盲评：只看图与案例意图，按 1–5 分打分，不看 answer key。
6. 评分结束后打开 `answer-key.json` 归组，统计每组中位分。

## 三、评分维度（1–5）

| 维度 | 判断标准 |
| --- | --- |
| 意图一致 | 画面是否表达了用户真正要的主体、动作、场景 |
| 结构正确 | 构图、镜头、空间关系是否成立，有无肢体/物体错误 |
| 细节有效 | 新增细节是否服务于画面，而不是堆词 |
| 风格达成 | 光影、材质、画风是否符合目标 |
| 无冲突/无伪影 | 是否出现互斥元素、文字乱码、明显伪影 |

允许备注具体失败原因（如「多手指」「光源方向矛盾」「服装朝代错误」）。

## 四、判定规则

- **C 优于 B**：C 在「意图一致」「结构正确」中位不低于 B，且在「细节有效」「风格达成」至少一项更高；同时「无冲突/无伪影」不下降。
- **C 不优于 B**：C 任一核心维度中位低于 B 超过 0.5 分，或冲突项下降。
- **A 作为下界**：A 明显低于 B/C 时，说明词库/编排确实带来增益；A 与 C 持平则要警惕过度编排。
- 样本量小，结论只针对所测案例；不得外推为「全面优于」。

## 五、记录与边界

- 记录底模、LoRA、采样器、步数、CFG、分辨率、种子、是否启用 refiner/增强。
- 同一案例三版必须使用完全相同的工作流；换模型或换参数即作废。
- 盲评至少一人完成；有条件时两人独立评分后取平均，并记录分歧项。
- 本协议比较的是**出图效果**，不替代检索评测（Recall/排序）与文本层面的一致性检查。
